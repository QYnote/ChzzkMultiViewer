# MultiStream — Chrome 확장 프로그램

> **다루는 내용:** 설치·사용 방법과 설계 문서 진입점  
> **갱신 트리거:** 설치/사용 절차가 바뀌거나 하위 설계 문서 구성이 바뀔 때

치지직(Chzzk), SOOP 등 인터넷 방송 스트리머 여러 명을 동시에 한 화면에서 시청할 수 있는 Chrome MV3 확장 프로그램입니다.

> ⚠️ 공식 개발자 API를 사용하지 않습니다. 브라우저에 저장된 로그인 세션 쿠키 방식만 사용합니다.

## 설치 방법

[크롬 웹 스토어 — MultiStream](https://chromewebstore.google.com/detail/multistream/aapiemaagmikgejakejdlicklbdjhnal)에서 **Chrome에 추가**를 누르면 됩니다. 업데이트는 자동으로 받습니다.

**개발 중인 소스로 설치하려면** (웹 스토어 버전과는 다른 확장으로 취급되어 저장한 데이터가 이어지지 않습니다)

1. 이 레포지토리를 다운로드(ZIP) 또는 클론합니다.
2. Chrome 주소창에 `chrome://extensions` 입력
3. 우측 상단 **개발자 모드** 토글 활성화
4. **압축해제된 확장 프로그램 로드** 클릭 → `source/` 폴더 선택
5. 확장 아이콘이 toolbar에 나타나면 완료

> 팔로잉 목록 연동과 로그인 상태 시청은 **해당 플랫폼에 로그인된 상태**에서만 동작합니다.

## 사용 방법

1. 확장 아이콘을 눌러 팝업을 열고, 볼 스트리머를 고릅니다 — [볼 채널 정하기](document/Requirements/Functions/Channel-Selection.md)
2. `멀티뷰 대시보드 열기`로 대시보드를 엽니다
3. 칸을 나누고 크기와 자리를 조절해 시청합니다 — [여러 방송 동시 시청](document/Requirements/Functions/Multiview/README.md)

할 수 있는 일 전체는 [기능](document/Requirements/Functions/README.md)에 정리되어 있습니다.

## 업데이트 예정 기능

- [ ] 트위치(Twitch) 플랫폼 채널 멀티뷰 지원 추가
- [ ] 팝업 화면을 이루는 파일들이 서로의 변수를 이름으로 직접 가져다 쓰는 구조 정리
  - 파일을 읽어 들이는 순서가 바뀌면 오류 없이 조용히 깨진다. 저장소를 읽는 쪽이 화면 요소를 직접 만지고 있어 경계도 흐리다

**개발 제외 항목**

- 통나무 파워 자동 수령 — 채팅창에 수령 버튼이 나타나면 자동으로 클릭 (네이버에서 작업장(매크로)으로 판단할 수 있는 위험이 있어 보류)
- 대시보드를 열 때 모든 방송을 소리 없이 시작 — **한 번 만들었다가 되돌렸다.** 칸마다 소리를 따로 다룰 수 없어서다. 소리는 방송 화면 안의 조절 기능에 맡기고, 원하지 않는 칸은 사용자가 직접 끈다
  - 치지직은 음량을 **채널마다 따로** 기억하지만, SOOP은 **전체를 하나로** 관리한다. 그래서 SOOP 칸 하나만 따로 끄거나 켜는 것이 성립하지 않는다
  - 음량 값을 덮어쓰는 방식은 **어느 경우에도 쓸 수 없다.** 방송 페이지가 그 값을 저장해, 다시 열 때 화면에 보이는 크기와 실제 소리가 어긋난다

## 일시적 오류 기록

재현이 되지 않아 확정 버그(업데이트 예정 기능)로 등록하지는 않았지만, 한 번 발생했던 오류를 날짜와 함께 기록합니다. 이후 새로운 버그가 발견되거나 Todo 항목을 추가할 때, 이 목록에 해당하는 내용이 있는지 먼저 확인합니다.

- **2026-10-07 — 치지직 칸 영상이 넓은 화면으로 바뀐 직후 멈춤**
  - 증상: 칸 화면이 멈춘 채 딜레이만 늘어난다. 재생 버튼은 보이지 않고, 눌러도 다시 나오지 않는다. 자동 동기화가 그 칸을 다시 읽어도 또 멈춘다. 대시보드 전체를 새로고침하면 풀리기도 한다
  - 진단 기록으로 확인한 것: 멈춘 9건 모두 **넓은 화면 버튼을 누른 직후**였다. 그때 영상은 일시정지 상태가 아니었고, 앞쪽 데이터도 충분히 받아 두었는데 **재생 위치만 넘어가지 않았다.** 버튼은 영상마다 한 번만 눌렸다
  - 원인이 아닌 것: 소리 재생 차단(직접 눌러도 안 풀림), 칸 위 덮개(클릭을 통과시킴), 저작권 보호 재생(일반 방송으로 확인)
  - 한 자리에서 9번 나온 뒤로 다시 나오지 않았다. 같은 날 "열자마자 칸을 한 번 더 읽는 문제"를 고쳤는데, 쓸데없이 다시 읽을 때마다 멈출 기회가 늘었으므로 덜 나오게 됐을 수 있다. 그것만으로 해결됐다는 근거는 없다
  - 다시 나오면: 영상 상태(일시정지 여부·준비 단계·재생 위치·받아 둔 데이터 끝)와 넓은 화면 버튼을 누른 시점을 기록해 이번 기록과 맞춰 본다. 살리는 방법으로 **재생 위치를 받아 둔 데이터 안쪽으로 조금 옮기기**를 실험하려 했으나, 멈춤이 다시 나오지 않아 효과를 확인하지 못했다
