# TechStack

> **다루는 내용:** 기술 선택과 선택 근거
> **갱신 트리거:** 쓰는 기술을 바꾸거나 더할 때

## 본문

| 영역 | 고른 것 | 근거 |
|---|---|---|
| 실행 환경 | 크롬 확장 프로그램 (Manifest V3) | 크롬 확장의 현행 규격이다.[^1] |
| 언어 | 순수 JavaScript · HTML · CSS | 빌드 과정 없이 소스 폴더를 그대로 불러와 실행할 수 있다.[^2] |
| 데이터 보관 | 확장 프로그램 전용 브라우저 로컬 저장소 | 사용자 기기 밖으로 나가지 않는다. 담는 것이 목록 몇 개와 설정뿐이라 단순한 이름·값 저장으로 충분하다.[^3] |
| 요청 고치기 | 선언적 네트워크 규칙 | 로그인 쿠키 싣기, 끼워 넣기 제한 걷어 내기를 규칙으로 걸어 둔다. 현행 규격에서 요청을 고치는 방법이다.[^4] |
| 플랫폼 차이 | 플랫폼마다 같은 모양의 어댑터 — [Platforms](Logical-Viewpoint/Platforms.md) | 치지직·SOOP 차이를 한곳에 모아, 새 플랫폼을 더할 때 어댑터 하나만 만들면 되게 한다 |
| 플랫폼 정보 얻기 | 브라우저에 남은 로그인 세션으로 플랫폼의 내부 조회 주소를 부른다 | 공식 개발자 기능은 쓰지 않는다.[^5] |

**주의**
- ⚠️ 플랫폼이 내부 조회 주소나 응답 모양, 방송 페이지의 화면 구조를 바꾸면 그 기능이 멈춘다. 공식 기능이 아니므로 미리 알려 주지 않는다. 플랫폼마다 기대는 값은 [치지직](Development-Viewpoint/Platforms/Chzzk.md) · [SOOP](Development-Viewpoint/Platforms/Soop.md)에 모아 둔다.

[^1]: 이전 규격(Manifest V2)은 크롬에서 지원이 끝나고 있다.
[^2]: 탈락한 대안 — 타입을 붙이는 언어나 화면 프레임워크. 둘 다 빌드 과정과 도구가 늘어나는데, 이 프로젝트는 파일 수가 적고 개발자가 웹 개발 경험이 없어 더해지는 단계를 줄이는 쪽을 택했다.
[^3]: 탈락한 대안 — 브라우저 내장 데이터베이스(조회 기능이 필요 없고 다루기 번거로움), 외부 서버(서버를 운영해야 하고 사용자 정보가 밖으로 나감). 이 저장소도 확장 권한으로 받아야 쓸 수 있다 — [배포와 설치 환경](Physical-Viewpoint/Deployment.md#설치-때-받는-권한).
[^4]: 요청을 하나하나 가로채 고치는 이전 방식은 현행 규격에서 일반 확장에 막혀 있다.
[^5]: 공식 개발자 기능은 신청·승인 절차와 사용량 제한이 있다. 사용자는 이미 플랫폼에 로그인해 있으므로 따로 인증할 필요가 없다는 점을 택했다 — 최상위 [README](../README.md)의 원칙.
