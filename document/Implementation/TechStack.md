# TechStack

> **다루는 내용:** 기술 선택과 선택 근거
> **갱신 트리거:** 쓰는 기술을 바꾸거나 더할 때

## 본문

| 영역 | 고른 것 | 근거 |
|---|---|---|
| 실행 환경 | Chrome 확장 프로그램 Manifest V3 | 크롬 확장의 현행 규격이다.[^1] |
| 언어 | 순수 JavaScript · HTML · CSS (번들러·트랜스파일러 없음) | 빌드 과정 없이 소스 폴더를 그대로 불러와 실행할 수 있다.[^2] |
| 데이터 보관 | `chrome.storage.local` | 기기 밖으로 나가지 않고, 담는 것이 목록 몇 개와 설정뿐이라 이름·값 저장으로 충분하다.[^3] |
| 요청 고치기 | `declarativeNetRequest` 동적 규칙 | 로그인 쿠키 싣기, 끼워 넣기 제한 걷어 내기를 규칙으로 걸어 둔다. MV3에서 요청을 고치는 방법이다.[^4] |
| 모듈 사이 연락 | 확장 메시지 · 창 사이 메시지(`postMessage`) · 저장소 변경 감지 | 실행 환경이 갈라져 있어 함수 호출이 안 된다 — [모듈](Modules/README.md#3-통신-규칙) |
| 플랫폼 차이 | 플랫폼마다 같은 모양의 어댑터 — [Platforms](Modules/Platforms.md) | 새 플랫폼을 더할 때 어댑터 하나만 만들면 된다 |

[^1]: 이전 규격(Manifest V2)은 크롬에서 지원이 끝나고 있다.
[^2]: 탈락한 대안 — TypeScript, React·Vue 같은 프레임워크. 둘 다 빌드 도구와 단계가 늘어나는데, 이 프로젝트는 파일 수가 적고 개발자가 웹 개발 경험이 없어 더해지는 단계를 줄이는 쪽을 택했다.
[^3]: 탈락한 대안 — IndexedDB(조회 기능이 필요 없고 다루기 번거로움), 외부 서버(운영 부담, 사용자 정보가 밖으로 나감). `storage` 권한이 필요하다 — [빌드·배포](Build-Deploy.md#권한-선언)
[^4]: 요청을 하나하나 가로채 고치는 `webRequest` 차단 방식은 MV3에서 일반 확장에 막혀 있다.
